# Codex Memory 周度整理 SOP

## 目的

将本机 Codex 最近一周产生的、已被真实任务验证的工作经验，沉淀到本仓库的可迁移配置包中。目标是提升下一台干净环境的 Codex 初始化质量，而不是备份或公开历史会话。

## 输入与输出

**允许读取的输入**：最近七天的本机历史会话元数据、用户明确指令、已验证的任务结果、当前自建 Skill 目录与本仓库现有内容。

**允许提交的输出**：工作原则、任务工作流、能力地图、Skill 清单、脱敏自建 Skill 源码、非敏感配置模板和本 SOP。

**绝不提交的输入或输出**：原始会话文本、API Key、令牌、Cookie、密码、私钥、私人地址、生产数据、客户资料、机器专属路径、缓存、日志和真实网络路由配置。

## 每周执行步骤

1. 只读查看最近七天会话；识别新增的任务类型、反复出现的偏好、已验证技术结论和用户明确要求沉淀的能力。
2. 将候选内容分为：可验证事实、用户偏好、可复用工作流、候选 Skill、仅限当前机器的状态。后一类不进入仓库。
3. 只有当方法已经在真实任务中验证、输入输出稳定且边界明确时，才创建或更新 Skill；否则更新工作流文档而不强行 Skill 化。
4. 写入时只使用概括后的规则和脱敏模板，不复制原始对话或配置内容。
5. 运行 `scripts/audit.sh`、相关脚本语法检查和 `git diff --check`。
6. 人工检查变更是否含私有数据、敏感模式、真实机器路径或未经验证的结论。
7. 若检查通过且有实质更新，提交并推送；若无实质更新，记录“本周无可迁移增量”，不创建空提交。

## Skill 纳入标准

- 已在至少一个真实任务中完成验证。
- 触发场景、输入、输出、依赖与失败边界可被清晰写出。
- 不依赖凭据、个人设备或未公开运行状态；若依赖本机工具，必须明确标为前置条件。
- 自带脚本时，脚本须经过语法/基础运行检查，且不包含敏感信息。

## 完成标准

- 本仓库仍能在干净环境中阅读和使用。
- 新增内容均有明确来源类别和验证状态。
- 安全扫描通过，Git 工作区干净。
- 本周变化已同步远端；或明确确认没有可迁移变化。
