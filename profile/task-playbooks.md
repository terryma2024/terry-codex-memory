# 任务工作流

## 机器人与仿真

1. 定义每个系统的权威边界：仿真世界、规划场景、控制器和真实状态查询。
2. 先以最小动作复现，并写出预期结果。
3. 分别验证规划、执行、物体附着、碰撞场景和关节/TF 事实；相机 topic 注册不算数据证据，还要检查真实 RGB、深度和 CameraInfo 的尺寸、编码、时间戳、frame 及有限正深度。
4. 修改后重新构建并加载目标运行产物，同时核对源码提交、安装前缀、可执行入口、动态依赖和进程命令；外部源码树的构建与测试必须使用相同发现范围，并先确认发现了目标包和测试，`0 packages` 或 `0 tests` 的成功退出不算通过。
5. 仅在自动测试、运行时状态和本轮新视觉证据一致后推进状态；失败按已产生的副作用恢复。
6. 将仿真结论标为仿真证据；真实设备另设安全授权、限速、限位、急停和相关性验收门。

## LLM/Agent 驱动高影响执行

1. 先冻结可表达的任务 schema 与非目标；模型只生成候选意图，不生成执行授权、任意命令、轨迹、速度或底层接口调用。
2. 用确定性 validator 校验类型、枚举、参数范围和上下文条件，再由 dispatcher 映射到显式能力白名单；未知或语义无效输入 fail closed。
3. 将 planner/provider、校验与调度、执行端口分层；预览只证明候选通过静态门，runtime 返回成功只证明入口完成，物理或业务结果仍需闭环证据。
4. provider fallback 只处理认证、网络、超时、HTTP 或响应解析等 provider 层失败；已解析但语义无效的候选直接终止，不能降级到另一个模型重试。
5. 排障时先在子进程中只输出敏感环境变量的 `SET`/`UNSET`，再绕过 fallback 单独调用主 provider；保留安全错误类别，不记录凭据或完整响应。

## 长时实验与多后端迁移

1. 启动前恢复最近有效 checkpoint，冻结来源提交、工作树、安装前缀、运行入口、后端、环境隔离标识和验收合同；已有账本为终止态时新建批次，不续写旧编号。
2. 将完整重启、世界重置和复用既有进程视为不同生命周期；不同生命周期、后端或实现版本的结果不混算连胜或资格。
3. 先保留已通过资格的实现作为行为基线，把环境差异收敛到明确的 backend/port；兼容入口保持薄层，真实硬件默认 fail-closed 或 plan-only。
4. 每次运行记录 `VALID`/`INVALID`、失败边界和恢复结果；单次成功、历史成功或替代后端成功不能代替规定次数的当前批次验收。
5. 合并或发布前同时检查源码树、安装产物、忽略文件残留、打开句柄和实际运行入口，避免已删除的旧实现仍被残留产物加载。
6. 只在自动测试、运行态 provenance、规定生命周期和用户可见闭环证据全部一致时宣布资格成立。

## 复杂系统差异与桌面异常诊断

1. 对齐两条系统的输入、调用链、控制合同、单位、频率和验收阈值，定位第一个输出开始分叉的边界，再调查下游现象。
2. 用一次只改变一个因素的最小 A/B 验证触发源；时间相关性先标为推断，能稳定复现后才升级结论。
3. 区分“检测器报错”和“被测系统失效”：放宽 tolerance、删除告警或延长等待只能证明检测行为变化，不能证明根因消失。
4. 诊断图形会话时以会话管理器、桌面总线、窗口属性和新截图交叉验证；SSH shell 的环境变量不代表真实图形会话，权限责任主体必须从现场父进程链确认。
5. 窗口验收绑定当前 window ID、owner、标题和 bounds，并检查原始分辨率内容；全屏图、坐标裁剪、旧 ID、旧截图或“没有权限弹窗”都不能替代精确窗口证据。
6. 修复或停止时只作用于已核验的配置项、窗口或 PID，并确认触发源没有再次生成问题。

## 研究、数据业务与 BP

1. 记录原始来源、时间、抓取状态和来源台账；失败或降级抓取保留为限制，不能升级成完整证据。
2. 抽取可验证事实，并单列推断、访谈说法与待验证假设。
3. 技术商业调研分别标注作者实验、独立复现、产品存在、客户/交易/财务证据和待验证项；论文指标、合作新闻或项目页面不能直接证明 SLA、收入、复购或规模化部署。
4. 数字按口径拆分；销量、销售额估算、公司收入、利润和预测值不能混加或互相替代。
5. 映射到当前产品、客户、技术、成本或 BP 缺口，并写出下一步可执行验证。
6. 数据处理保留 `raw → canonical dataset → model view`：raw 不被训练增强覆盖；任务、动作空间、坐标系、时间基准和 episode 边界先冻结；失败、接管和恢复样本保留并进入真实留出验收。
7. 形成带来源的可复用文档；对外版本清理内部元数据但保留公开来源和证据边界，同步后回读验收。
8. 硬件选型区分芯片/平台与完整整机，并核对具体 SKU、内存/存储、接口、软件栈、售后和支持模型；报价注明日期与来源，税费按最终收货地址估算，汇率折算与运输、关税、增值税和渠道成本分列。

## 表格模板与数据模型迁移

1. 在改解析器或写入逻辑前，先比较新旧文件的工作表名、表头、列顺序、合并单元格、关键区域和示例值，形成明确差异表。
2. 区分文件模板、外部源表、应用规范化模型和数据库物理 schema；回答当前目标结构时以运行代码与 schema 为准，旧文档用于解释设计意图。
3. 为重命名、增删列、空值、兼容别名、金额/日期类型和重复导入定义显式规则；不从一个改名推断整个布局未变。
4. 用代表性样本验证导入、更新、去重、明细关联与导出回读；没有读取实时外部表时明确标为未核验线上状态。

## 本地 Markdown 同步到在线文档

1. 用户指定本地文件为最新版本时，将其作为本轮唯一内容源；写入前记录在线目标和同步方式。
2. 在临时转换流中移除只供本地工具使用的元数据，并把不兼容的图表语法转换成目标平台支持的格式；不改写原文件。
3. 执行整篇覆盖；读权限不代表写权限，权限失败时切换到已授权身份，不重复无效写入。
4. 覆盖后重新获取当前文档，不复用旧块标识；核对修订、标题/章节、关键术语、媒体数量和警告。
5. 只有回读内容与本地源一致时才宣布同步完成。

## 生产修复与发布

1. 只读定位并复现真实问题。
2. 选择最小改动，补充回归覆盖。
3. 在本地运行相关质量门。
4. 发布后分别回读发布机制与运行状态；定时任务、部署配置或安装脚本必须核对线上生效状态，并按真实用户路径验收，记录证据与残余风险。

## 项目内 Skill 与远程开发

1. 先读取仓库指令和命中的项目内 Skill，确认触发条件、依赖、证据门与禁止事项。
2. 把目标、范围、已知状态、工作区保护规则、验收命令、视觉证据和停止条件整理成一次性 handoff。
3. 执行端独立完成最小闭环；协调端只在约定检查点、阻塞或偏差时介入，不逐条遥控。
4. 验收时检查真实会话、进程、构建/安装来源、测试退出码和本轮新视觉证据，不接受单独的完成声明。
5. 只有输入输出稳定、边界跨项目成立且真实任务验证充分时，才从项目工作流提炼通用 Skill。

## 作用域严格的 Git 操作

1. 分别检查根仓库、子模块或工作树的状态、分支和远端关系，把现有改动视为用户资产。
2. 只暂存明确点名的路径；子模块内部提交与根仓库指针更新视为两个独立决定。
3. 提交前运行当前环境可用的对应质量门和 `git diff --check`；若测试依赖缺失或测试未执行，记录为功能验证缺口，不把提交、推送或远端一致描述成测试通过。
4. 推送前同步远端，避免用强推掩盖分叉；推送后读取远端引用确认发布一致。未被授权的相关改动保持原状并在交付中说明。

## 远程网络与主机

1. 先确认连接、代理、进程、服务和目标机当前有效配置；连接别名必须经过主机身份验证，不能为绕过校验而接受未知目标。
2. 只同步明确受管的无凭据列表或模板，不复制含凭据的完整配置；保留独立恢复路径并为目标文件创建备份。
3. 对结构化配置采用局部、非冲突合并，保留目标机既有身份、通配段和本地策略；整体覆盖必须有用户明确授权。
4. 先验证候选配置，再原子替换或重启；失败时恢复备份。一次同步不自动扩展为持续跨机同步。
5. 修改后同时回读受管内容摘要、配置检查、服务状态和目标行为；通过真实外部请求验收，但不在输出中泄露路径、凭据、私有规则或完整日志。

## 进程调查与定向停止

1. 从当前 PID、完整命令、父子进程、会话和资源变化建立目标身份，不从进程名或过期采样直接下结论。
2. 先只读区分正常负载、异常忙循环和未知机制；证据不足时保留“未确认”。
3. 收到停止授权后先使用作用于该 PID 的正常终止；若目标仍存活，重新确认身份后再决定是否强制终止。
4. 操作后确认目标未重启，同时核对相邻服务、会话和恢复通道未受影响。
