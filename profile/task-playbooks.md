# 任务工作流

## 机器人与仿真

1. 定义每个系统的权威边界：仿真世界、规划场景、控制器和真实状态查询。
2. 先以最小动作复现，并写出预期结果。
3. 分别验证规划、执行、物体附着、碰撞场景和关节/TF 事实；相机 topic 注册不算数据证据，还要检查真实 RGB、深度和 CameraInfo 的尺寸、编码、时间戳、frame 及有限正深度。
4. Viewer/桌面录屏只证明对应画面可见且可采集；它不证明任务相机 RGB-D、感知输入、位姿估计或 pick-place 闭环成立，分别建立证据门。
5. 仿真器的对象 ID、真值位姿或合成标签只用于数据生成与评估，不得作为运行时感知、定位、里程计、SLAM 或 Nav2 输入。
6. 从点云、辐射场或 3DGS 构建 SimReady 资产时，拆分 `appearance/render mesh + collision proxy + physics/semantics + per-runtime adapter`；尺度与坐标变换同时作用于相机和几何，质量、质心、惯量、摩擦和关节不得从外观 checkpoint 猜测。
7. SimReady 验收分为规范/组合层、运行时层和任务层；分别检查资产结构、引擎加载与传感器、碰撞/动力学及目标任务，不能用“文件可导入”或渲染截图替代后两层。
8. 修改后重新构建并加载目标运行产物，同时核对源码提交、安装前缀、可执行入口、动态依赖和进程命令；外部源码树的构建与测试必须使用相同发现范围，并先确认发现了目标包和测试，`0 packages` 或 `0 tests` 的成功退出不算通过。
9. 仅在自动测试、运行时状态和本轮新视觉证据一致后推进状态；失败按已产生的副作用恢复。
10. 将仿真结论标为仿真证据；真实设备另设安全授权、限速、限位、急停和相关性验收门。

## 机器人示教、策略与安全执行

1. 先冻结 observation、state、action、坐标系和共同时间基准；`action[t]` 是该时间格已接受并正在执行的专家 reference，不能用下一帧实测关节位置冒充。
2. 相机、状态与动作按时间戳显式对齐，丢弃过期、不连续或跨 reset 的帧；教师专用深度、位姿、接触或仿真真值只用于生成、标签、评估和审计，不进入策略 observation。
3. 所有会写控制器的入口统一经过一个 broker/lease owner；多控制器部分接受失败、旧 goal 替换或超时必须触发同步停止，不能让既有客户端绕过仲裁。
4. 安全监督覆盖整条路径和整台机器人，包括自碰撞、环境碰撞、相机支架、桌面与持物风险；只检查目标物接触或起点 goal 不足以证明安全。
5. attempt 使用单调时钟和端到端预算，覆盖推理、重试、抓放、撤离与终态检查；预算耗尽后进入确定性停止或撤离，实机安全门缺失时保持 fail-closed/plan-only。
6. 将可调参的 Rollout Validation 与封存测试隔离，分别报告端到端成功率、已满足前置条件时的策略成功率和恢复干预；设计文档、离线指标或仿真成功不能替代实机验收。

## 并行批处理与资格判定

1. 由一个上游 coordinator 统一持有队列、动态租约、容量与完成计数、Worker/Broker 生命周期、结果提交、恢复、清理和批次资格；若系统还产生可复用准入画像，则由候选链之外的独立 authority 验证、接受和撤销，二者不能互相代写权威状态。
2. 扩容使用新版本契约，冻结协议、运行配置和资源画像；分别记录 requested、allocated、started 与 ready 容量，只有它们精确等于请求值才开放正式队列，不能用限流参数隐藏降级。
3. 运行前验证模式、并发度、最终容量、资源和运行 provenance，并把一次性 preflight receipt 绑定到本次 campaign/batch；按递增阶段在同一身份下准入，阶段 canary 使用独立命名空间，不进入正式覆盖率、成功率或资格分母。
4. 分开定义 point 终态与 attempt 终态，并显式限定哪些失败可重试；重试使用新的隔离批次、租约和证据，不覆盖第一次结果，也不把不确定状态改写成失败或成功。
5. slot 存活心跳与工作 lease 分离，epoch、generation、session 和 sequence 都参与 fencing；丢失 Worker 后先暂停新 lease，换代不重置已用配额或已裁决结果，恢复到请求的精确健康容量后才能继续。
6. 指标样本绑定 Worker generation、运行身份和单调时间；计划内 reset/recovery 是有界状态迁移而不是缺样豁免，未受影响的主机、隔离组和设备指标仍须连续，超时、缺样或身份漂移阻断准入。
7. journal、manifest、artifact namespace、cleanup receipt 和批次资格 flags 由 coordinator 原子提交并可回放；authority 只从封存证据重算画像，并在任何新准入前消费持久化的待撤销记录；Web snapshot、Worker 自报成功或旧 cursor 不能越权改变权威状态。
8. 恢复时先核对 campaign、batch、receipt、cursor、代际和已提交结果，再重建未完成工作；只有资源、执行、证据、权威裁决和清理门全部通过时才能宣布资格成立。

## LLM/Agent 驱动高影响执行

1. 先冻结可表达的任务 schema 与非目标；模型只生成候选意图，不生成执行授权、任意命令、轨迹、速度或底层接口调用。
2. 用确定性 validator 校验类型、枚举、参数范围和上下文条件，再由 dispatcher 映射到显式能力白名单；未知或语义无效输入 fail closed。
3. 将 planner/provider、校验与调度、执行端口分层；预览只证明候选通过静态门，runtime 返回成功只证明入口完成，物理或业务结果仍需闭环证据。
4. provider fallback 只处理认证、网络、超时、HTTP 或响应解析等 provider 层失败；已解析但语义无效的候选直接终止，不能降级到另一个模型重试。
5. 排障时先在子进程中只输出敏感环境变量的 `SET`/`UNSET`，再绕过 fallback 单独调用主 provider；保留安全错误类别，不记录凭据或完整响应。

## 长时实验与多后端迁移

1. 启动前恢复最近有效 checkpoint，冻结来源提交、工作树、安装前缀、运行入口、后端、环境隔离标识和验收合同；已有账本为终止态时新建批次，不续写旧编号。
2. 将完整重启、世界重置和复用既有进程视为不同生命周期；不同生命周期、后端或实现版本的结果不混算连胜或资格。
3. 先保留已通过资格的实现作为行为基线，把环境差异收敛到明确的 backend/port；兼容入口保持薄层，真实硬件默认 fail-closed 或 plan-only。
4. 每次运行记录 `VALID`/`INVALID`、失败边界和恢复结果；单次成功、历史成功或替代后端成功不能代替规定次数的当前批次验收。
5. 合并或发布前同时检查源码树、安装产物、忽略文件残留、打开句柄和实际运行入口，避免已删除的旧实现仍被残留产物加载。
6. 只在自动测试、运行态 provenance、规定生命周期和用户可见闭环证据全部一致时宣布资格成立。

## 复杂系统差异与桌面异常诊断

1. 对齐两条系统的输入、调用链、控制合同、单位、频率和验收阈值，定位第一个输出开始分叉的边界，再调查下游现象。
2. 用一次只改变一个因素的最小 A/B 验证触发源；时间相关性先标为推断，能稳定复现后才升级结论。
3. 区分“检测器报错”和“被测系统失效”：放宽 tolerance、删除告警或延长等待只能证明检测行为变化，不能证明根因消失。
4. 诊断图形会话时以会话管理器、桌面总线、窗口属性和新截图交叉验证；SSH shell 的环境变量不代表真实图形会话，权限责任主体必须从现场父进程链确认。
5. 窗口验收绑定当前 window ID、owner、标题和 bounds，并检查原始分辨率内容；全屏图、坐标裁剪、旧 ID、旧截图或“没有权限弹窗”都不能替代精确窗口证据。
6. UI 配色或视觉层级变更先统一语义 token，再运行测试与生产构建、核对实际服务加载的制品，并对受影响的明暗主题与关键宽度获取本轮新截图；未审查的状态明确保留为验证缺口。
7. 配置告警按用户配置、项目配置、命令行覆盖、会话 flags、共享 daemon 和最终 UI 分层追踪；找不到受支持的可编辑来源时，不添加猜测字段或伪造替代开关。
8. 修复或停止时只作用于已核验的配置项、窗口或 PID，并确认触发源没有再次生成问题。

## 研究、数据业务与 BP

1. 记录原始来源、时间、抓取状态和来源台账；失败或降级抓取保留为限制，不能升级成完整证据。
2. 抽取可验证事实，并单列推断、访谈说法与待验证假设。
3. 技术商业调研分别标注作者实验、独立复现、产品存在、客户/交易/财务证据和待验证项；论文指标、合作新闻或项目页面不能直接证明 SLA、收入、复购或规模化部署。
4. 商业投资任务先给 thesis、估值锚、催化剂、风险、证伪条件和监测指标；将上市可交易标的、非上市公司和系统级产业参照分开，不把集团口径、媒体估值或单卡峰值性能伪装成同口径可比数据。
5. 估值快照冻结交易日、官方股本和计算公式，并把客户集中、扣非利润、经营现金流、软件迁移、集群利用率和单位请求成本纳入可比边界；网页动态市值只能作为线索，不作为固定日期结论。
6. 论文分析按正文与附录定位训练数据、阶段、损失、硬件和实验设置；论文未报告的学习率、权重或实现细节明确标为缺失，解释性推断不能写成复现参数。
7. 数字按口径拆分；销量、销售额估算、公司收入、利润和预测值不能混加或互相替代。
8. 映射到当前产品、客户、技术、成本或 BP 缺口，并写出下一步可执行验证。
9. 数据处理保留 `raw → canonical dataset → model view`：raw 不被训练增强覆盖；任务、动作空间、坐标系、时间基准和 episode 边界先冻结；失败、接管和恢复样本保留并进入真实留出验收。
10. 形成带来源的可复用文档；对外版本清理内部元数据但保留公开来源和证据边界，同步后回读验收。
11. 硬件选型区分芯片/平台与完整整机，并核对具体 SKU、完整套件/配件边界、内存/存储、接口、软件栈、售后和支持模型；只有实时详情或结算价格、库存与配送上下文均已确认时才声称“最低价”。报价注明日期与来源，税费按最终收货地址估算，汇率折算与运输、关税、增值税和渠道成本分列。
12. 共享来源台账先同步远端再最终分配 ID；若远端占用暂定编号，只重编号本轮新增材料，并同时校验台账字段、manifest 字段、原文路径、链接、索引和必需章节，不为消除格式告警而重写原始证据。

## 测试套件分层与基准测试

1. 按反馈速度和触发频率把日常快速测试与低频基准测试分开；默认入口必须稳定排除基准目录，基准入口则显式选择该目录。
2. 用独立的分区契约测试断言两套用例不会互相泄漏，并在项目规则中写明触发条件、入口、环境与预计成本。
3. 修改普通业务代码时运行快速门；修改基准实现、评估报告/适配器或比较、选择模型时，额外运行完整基准门。
4. 分别记录两套门发现的用例数、退出码、耗时与环境来源；零发现、错误解释器、裸源码导入或错误 overlay 的成功退出都不算通过。
5. 若统一测试运行器被既有动态库或平台环境阻塞，可用同一构建产物执行等价的直接测试定位边界，但必须保留未通过统一入口的平台验证缺口。

## CLI 与运行环境排障

1. 在与用户相同的 shell 模式下解析命令路径、shebang/启动器和实际解释器；非交互 SSH 与登录 shell 的 PATH 差异必须先显式复现。
2. 检查失败依赖属于系统环境、项目虚拟环境还是工具专用环境，不把包安装到另一个能运行 Python 但不拥有该命令的解释器；zsh 下带 extras 的包名使用引号，例如 `'package[extra]'`。
3. 只在已确认的归属环境内做最小依赖修复，不修改无关代理、系统 Python 或其他服务。
4. 修复后先验证导入或传输层构造，再运行一条真实但无破坏性的 API/CLI 请求；包管理器成功退出只证明安装完成。问题属于远端主机时，本地复现只能解释机制，完成结论必须来自目标主机输出。
5. 权限错误先做轻量能力预检，缺失授权由用户补齐；不得读取、打印或转存令牌来“验证”权限。
6. 若 CLI 连接共享 daemon 或 app-server，核对两端版本、启动时间和缓存状态；系统依赖修复后仍有旧告警时，先证明它来自旧进程，再说明会话影响、取得授权并重启，最后从完整交互入口复验。

## 硬件设备与固件变更

1. 先只读列举设备并核对型号、当前固件、连接模式和目标设备；多设备场景必须显式选择目标，不能依赖枚举顺序。
2. 将本机工具的 `--help`、安装版本源码和厂商支持矩阵交叉核对；文档出现而本版本 CLI 未注册的参数不得直接使用，固件必须明确支持目标 SKU。
3. 普通设备使用厂商签名的正常升级路径；recovery 只用于已进入恢复态的设备，未签名固件只用于明确解锁且已授权的场景，不把特殊模式当通用重试手段。
4. 关闭占用设备的程序，使用稳定供电与合适的数据链路；更新中不拔插、不并行操作其他设备，并在可用时先完成备份和恢复准备。
5. 只有在用户授权后真实执行、设备重新枚举且核心功能复验通过，才宣布固件更新完成；命令示例、下载完成或文档核对都只是准备证据。

## 源码级架构与性能分析

1. 从项目入口、锁文件和依赖清单确定真实仓库根目录、版本、后端与配置；不要用同名 sibling checkout 或更新分支替代锁定版本。
2. 沿入口到核心循环追踪数据形状、所有权、设备驻留、复制边界、stream/event 和阶段顺序，区分源码明确事实与推断。
3. 将零拷贝、同一 GPU、CUDA Graph 和多卡同步分别解释；共享存储或复用设备不自动证明仿真、推理与反向传播并行。
4. 对训练/批处理系统分别记录 rollout/采集阶段、更新阶段和跨设备同步；没有 profiler 或基准时，不报告吞吐、重叠比例、显存上限或收敛速度。
5. 若未安装依赖或未运行任务，明确标为静态分析；给出的 smoke-test、正式运行和发布建议保持为后续验证步骤。

## 模型 Provider 配置与路由

1. 分开定义 provider、模型 catalog、活动 profile、模型选择界面和请求路由；配置中出现多个 provider 不等于一个列表能合并展示或按模型正确分流。
2. 凭据只从环境或本机安全 helper 注入；诊断 helper 时验证退出码与 `SET`/`UNSET`，不打印值，也不把密钥写入 catalog、profile 或证据。
3. “桌面应用和命令行都配置”要求分别从两个入口读取真实模型列表并执行最小请求；TOML/JSON 可解析、文件已保存或 profile 可切换都不是运行时验收。
4. 需要统一模型选择器时，验证每个模型选择是否把 provider 标识传到线程和实际请求；仅拼接 catalog 而没有 provider-aware routing 属于未完成方案。
5. 记录当前客户端/服务端版本和未支持边界；配置形状、模型列表与路由能力可能随版本漂移，升级后重新验证。

## 桌面应用与浏览器控制故障

1. 先做一次最小控制调用和一次有界重试，再检查应用/浏览器版本、活动 profile、扩展启用状态和受支持的宿主通信链路。
2. “浏览器可发现”或“扩展已安装”只算前置检查；恢复验收至少包含列出标签、创建或选择标签、导航，以及 DOM/文本回读。
3. 必须由用户完成的 UI 操作用短步骤交接；用户回复“已打开”或“已重装”后，立即重跑代理侧端到端探针，不把手工动作视为修复证据。
4. 新任务、应用/浏览器重启和支持的重装路径均失败后，停止重复干预，保留错误类别与路由证据并按官方渠道升级；不私自修补宿主、改用未授权的旁路自动化或声称已恢复。

## 系统重装与存储规划

1. 先确认磁盘数量与实际容量、RAM、是否休眠/双系统、加密和远程无人值守启动要求，再决定 EFI、boot、swap 和逻辑卷结构。
2. 以用途划分系统、可变服务数据、用户配置和大容量工作数据；优先保留卷组空闲空间与可扩展目录，而不是把所有余量一次性切满。
3. 单独核对 Docker/containerd 的版本、存储后端和实际数据目录，再决定 `/var` 容量或迁移方案；默认路径只是候选，不是现场事实。
4. 同盘数据卷可降低重装误删风险，但不构成备份；加密解锁、休眠 swap 和远程重启之间的冲突须在安装前明确。
5. 在约束未齐全时只提供带假设的容量示例，不生成可直接执行的分区命令；最终方案须用目标机磁盘清单和安装策略回读确认。

## 模型、数据与制品发布

1. 从来源运行、训练配置、数据 manifest、评估记录与哈希共同确定待发布制品；拒绝仅按 `best`、`latest` 等通用文件名选择。
2. 大规模准备前先做目标仓库权限、可见性和轻量写入预检，并以用户最后一次明确的公开/私有要求为准。
3. 在临时 staging 中只复制 manifest 明确列出的模型、数据、便携配置、指标、来源说明、评估样例和校验和；排除绝对路径、缓存、凭据和机器状态。
4. 上传中断或限流时按平台支持的正常增量方式恢复，不以强制重下或重新上传放大请求量。
5. 发布后从远端重新下载或列举有效载荷，比较文件集合与哈希，并单独回读可见性、门控和匿名访问；远端仓库存在不等于内容完整或公开设置正确。

## 表格模板与数据模型迁移

1. 在改解析器或写入逻辑前，先比较新旧文件的工作表名、表头、列顺序、合并单元格、关键区域和示例值，形成明确差异表。
2. 区分文件模板、外部源表、应用规范化模型和数据库物理 schema；回答当前目标结构时以运行代码与 schema 为准，旧文档用于解释设计意图。
3. 为重命名、增删列、空值、兼容别名、金额/日期类型和重复导入定义显式规则；规范名称查询要覆盖历史别名，展示与修复输出统一规范化，默认不为改名做破坏性历史数据迁移。
4. 用代表性样本验证导入、更新、去重、明细关联与导出回读；没有读取实时外部表时明确标为未核验线上状态。

## 本地 Markdown 同步到在线文档

1. 用户指定本地文件为最新版本时，将其作为本轮唯一内容源；写入前记录在线目标和同步方式。
2. 在临时转换流中移除只供本地工具使用的元数据，并把不兼容的图表语法转换成目标平台支持的格式；不改写原文件。
3. 执行整篇覆盖；读权限不代表写权限，权限失败时切换到已授权身份，不重复无效写入。
4. 覆盖后重新获取当前文档，不复用旧块标识；核对修订、标题/章节、关键术语、媒体数量和警告。
5. 只有回读内容与本地源一致时才宣布同步完成。

## PDF 与打印交付

1. 打印前验证 PDF 页数、纸张尺寸、版面数量、题目/答案模式、关键文本与字体可读性；文件成功生成不能替代内容检查。
2. 明确纸张、缩放、单双面、份数和目标打印队列后再提交，避免依赖打印机默认值。
3. 提交成功只证明任务进入队列；继续检查未完成队列、任务最终状态和打印机是否恢复空闲。
4. 只有内容验证、队列完成和设备空闲三项都成立时才宣布物理打印完成；若无法观察纸面结果，明确保留实物外观未核验。

## 生产修复与发布

1. 只读定位并复现真实问题。
2. 选择最小改动，补充回归覆盖。
3. 在本地运行相关质量门，并从已确认提交生成干净发布制品；脏工作树中的无关修改、删除或临时证据不得进入同步包。
4. 临时运维访问采用“先加入并验证新路径，再离开旧路径”，保留恢复方式；清理权限不足时不得扩大 IAM/ACL 或强制删除，可使用已授权的非破坏性保留策略，并在结束后移除临时配置。
5. 发布后回读目标版本和发布机制，再分别检查应用、代理、数据库、迁移、维护模式、鉴权边界和真实用户入口；命令成功或容器运行不能代替这些检查。
6. 恢复防火墙、安全组、临时环境文件和其他运维状态，回读最终配置并确认没有遗留访问路径；版本、健康和安全恢复三者齐全后才宣布生产发布完成。

## 项目内 Skill 与远程开发

1. 先读取仓库指令和命中的项目内 Skill，确认触发条件、依赖、证据门与禁止事项。
2. 把目标、范围、已知状态、工作区保护规则、验收命令、视觉证据和停止条件整理成一次性 handoff。
3. 执行端独立完成最小闭环；协调端只在约定检查点、阻塞或偏差时介入，不逐条遥控。
4. handoff 或队列 receipt 只证明已接收；验收时检查真实会话、进程、构建/安装来源、测试退出码、产物、清理和本轮新视觉证据，不接受单独的完成声明。
5. 远程执行窗或 tmux pane 丢失时，从最新账本、同一运行身份和 checkpoint 恢复；先核对仍存活的 Worker/租约，避免重复执行、双重控制或覆盖已有证据。
6. 压缩或重构 Skill 时先列出必须保留的安全合同、证据门、触发条件和失败边界；删除重复导航或示例不能弱化合同，源码与合同存在漂移时同时保留“当前实现事实”和“目标要求”，不得把未实现要求写成已通过。
7. 只有输入输出稳定、边界跨项目成立且真实任务验证充分时，才从项目工作流提炼通用 Skill。

## 作用域严格的 Git 操作

1. 分别检查根仓库、子模块或工作树的状态、分支和远端关系，把现有改动视为用户资产。
2. linked worktree 若出现与现场不符的大量删除或未跟踪文件，先解析 `.git` 指针、gitdir、common dir 和 work tree，并用显式 `--git-dir`/`--work-tree` 复核文件哈希；未确认前不清理、不暂存。
3. `git pull` 因分叉停止时，先确认工作树、ahead/behind、本地独有提交、路径重叠、子模块 pin 和远端最新状态，再选择 rebase 或 merge；不要直接照抄 Git 的通用提示。需要固定策略时优先使用仓库局部配置。
4. 只暂存明确点名的路径；子模块内部提交与根仓库指针更新视为两个独立决定。
5. 提交前运行当前环境可用的对应质量门和 `git diff --check`；若测试依赖缺失或测试未执行，记录为功能验证缺口，不把提交、推送或远端一致描述成测试通过。
6. 多远端存在独立历史时，先 fetch 并分别比较提交图、patch-id、tree 和内容差异；在隔离 clone/worktree 生成候选，保留双方独有提交，禁止用强推或机械快进抹平历史。
7. 普通推送后分别回读目标远端引用和 tree；一轮推送被中止时先检查远端实际状态再重试。同步后仍领先远端的提交继续标为本地未发布，除非用户明确授权推送。

## 远程网络与主机

1. 先确认连接、代理、进程、服务和目标机当前有效配置；连接别名必须经过主机身份验证，不能为绕过校验而接受未知目标。
2. 只同步明确受管的无凭据列表或模板，不复制含凭据的完整配置；保留独立恢复路径并为目标文件创建备份。
3. 对结构化配置采用局部、非冲突合并，保留目标机既有身份、通配段和本地策略；整体覆盖必须有用户明确授权。
4. 先验证候选配置，再原子替换或重启；失败时恢复备份。一次同步不自动扩展为持续跨机同步。
5. 修改后同时回读受管内容摘要、配置检查、服务状态和目标行为；通过真实外部请求验收，但不在输出中泄露路径、凭据、私有规则或完整日志。

## 进程调查与定向停止

1. 从当前 PID、完整命令、父子进程、会话和资源变化建立目标身份，不从进程名或过期采样直接下结论。
2. 先只读区分正常负载、异常忙循环和未知机制；证据不足时保留“未确认”。
3. 收到停止授权后先使用作用于该 PID 的正常终止；若目标仍存活，重新确认身份后再决定是否强制终止。
4. 操作后确认目标未重启，同时核对相邻服务、会话和恢复通道未受影响。
